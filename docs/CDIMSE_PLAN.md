# C-DIMSE Support Plan

This plan records only behavior implemented and verified in this repository.
C-DIMSE support is not described as complete unless the command set, SCU path,
SCP dispatch path, response validation, cancellation behavior, and relevant
network flow are covered by tests.

## Remaining

| Area | Current status |
| --- | --- |
| C-CANCEL final cancel semantics | C-FIND, C-GET, and C-MOVE status handlers poll for pending C-CANCEL before final responses, and automatic C-MOVE polls between destination C-STORE sub-operations. The library still does not asynchronously terminate arbitrary application code while it is executing. |
| C-GET sub-operation orchestration | Same-association C-STORE sub-operation round trips are verified, including a reusable sequential multi-instance helper with aggregate counters and Message ID cancellation checks before sub-operations. This helper does not claim asynchronous operations or automatic handler interruption. |
| C-MOVE sub-operation orchestration | Destination C-STORE sub-operation round trips are verified using a resolver-provided endpoint, automatic destination association opening in C-MOVE dispatch, and reusable sequential helpers with aggregate counters and Message ID cancellation checks before sub-operations. The handler must still provide the retrieved instances and destination storage Presentation Contexts. |
| Service-specific status ranges | C-ECHO, C-STORE, Query/Retrieve C-FIND, C-GET, C-MOVE, and generic N-DIMSE Annex C status validators are verified. C-GET/C-MOVE retrieve sub-operation counter presence/multiplicity rules and Failed SOP Instance UID List presence/non-empty validation/emission for known failed sub-operations are covered for the tested statuses; other detailed service-class-specific failed/warning related fields are not complete. |
| Network end-to-end tests | Current tests cover command set construction, selected dispatch/SCU code paths, local P-DATA round trips, local N-DIMSE SCU/SCP P-DATA request/response paths, local A-ASSOCIATE primitive exchange with C-ECHO, local extended negotiation sub-item round trips, thread-backed C-ECHO/C-STORE/C-FIND/C-GET dispatch/C-MOVE dispatch/C-CANCEL dispatch/N-DIMSE dispatch, C-CANCEL polling by a running C-FIND handler, final C-FIND/C-GET/C-MOVE Cancel responses, one C-GET same-association C-STORE sub-operation, sequential multi-instance C-GET C-STORE sub-operations, automatic sequential multi-instance C-MOVE destination C-STORE sub-operations, and C-MOVE Cancel between destination sub-operations. |
| Extended negotiation behavior | SCP/SCU Role Selection, SOP Class Extended Negotiation, and Asynchronous Operations Window user-information sub-items are encoded, decoded, preserved in A-ASSOCIATE-RQ/AC, proposable through `ClientConnection`, and reflected in `ServiceBase` negotiated association state. Negotiated C-DIMSE and N-DIMSE SCU/SCP roles are enforced when association role state exists, and generic C-DIMSE/N-DIMSE SCU/SCP paths enforce the negotiated invoked/performed operation windows with Message ID tracking for locally outstanding confirmed requests and synchronous handler execution. The library does not yet implement asynchronous DIMSE operation scheduling. |
| N-DIMSE service-specific semantics | Generic N-DIMSE command transport, dispatch, role checks, and status class validation are covered. SOP-class-specific behavior for individual normalized service classes remains the responsibility of registered callbacks. |

## Execution Order

1. Implement asynchronous C-DIMSE operation scheduling only as a separate
   scheduler/dispatch change; `ServiceBase` now represents Message ID
   correlation and outstanding-operation limits, but no asynchronous DIMSE
   scheduler is claimed.
2. Add SOP-class-specific N-DIMSE callback tests only when concrete normalized
   service class behavior is implemented.
